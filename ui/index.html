    Cenários de falha

    Cada cenário derruba contentores reais, gera tráfego e confirma no fim que o dinheiro no sistema é o mesmo. Acompanhe no mapa.

    O administrador não movimenta contas. As transferências dos cenários são feitas automaticamente por dois clientes de teste (Ana e Diego), como num teste automático.

    Clientes e contas

    Os utilizadores vêm do serviço de autenticação; as contas, dos três fragmentos.

    Novo cliente

    Mínimo 8 caracteres, com letras e números. Entregue-a ao cliente.

    Primeira conta

    Abrir conta

    Bases de dados

    Cada nó lido diretamente, um a um. Cada região guarda só as suas contas; a réplica tem de ser igual ao primário; a tabela de taxas é igual em todos.

    Depositar

    Regista dinheiro que entra no banco, por exemplo um depósito ao balcão. O administrador pode creditar contas, mas nunca as pode debitar.

    O depósito é uma transação local no servidor da conta e fica na auditoria.

    Câmbio

    A tabela de taxas existe em cada servidor de dados. As cópias têm de ser iguais; uma alteração só passa se todas a aceitarem.

    Alterar uma taxa

    Feita com Two-Phase Commit em todas as cópias.

    Ficheiros no HDFS

    Relatórios e auditoria ficam no sistema de ficheiros distribuído, com cada bloco em dois DataNodes.

    Coordenador 2PC

    Transações que cada servidor da API coordenou e as que ainda estão preparadas à espera de decisão.

    Depois de uma promoção de réplica, reponha a topologia inicial no terminal com powershell -ExecutionPolicy Bypass -File scripts\reset-alta-disponibilidade.ps1.

    Entrar

    Use o seu utilizador e palavra-passe do Global-Scale System.

    A ligação é cifrada (HTTPS). A palavra-passe é verificada pelo serviço de autenticação, que devolve um token assinado válido 15 minutos.
